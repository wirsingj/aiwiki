# Instructions For Agents

Use YAIML as project memory for AIWIKI.

## YAIML Project Memory

Before meaningful work, read `yaiml.yml` and its core documents: SoT for current state, Architecture for system boundaries, and Maintainer Guide for procedures. Read each selected document's stable header before its body. Load supporting material only when task-relevant, reuse already-loaded context while current, and verify consequential claims against the repository.

Before finishing material work, update affected memory without a separate YAIML request. Respect read-only scope and review rules; report pending updates when writing is unavailable. Leave unchanged memory alone.

Replace the existing account of changed facts; do not append session summaries. Remove superseded claims and resolved active items in affected sections. Retain completed work only as a current capability, still-relevant decision or constraint, or lesson that changes future action. Keep one detailed home per fact and link from other roles. Do not move run history into supporting files merely to shorten the core.

Preserve human direction, evidence scope, uncertainty, unresolved contributor disagreements, and governed records. Measure affected documents before and after, check existing budgets, and compress safely first. Do not pad, inflate budgets, or delete necessary knowledge to meet a number. Report necessary net growth, why the knowledge must remain, and any retained overage and next action in the task response, not memory.

"Update YAIML", "updated YAIML", "check new YAIML", or "run a YAIML update" means refresh convention guidance from a human-provided, workspace-local, or team-approved reference. Preserve project memory and the existing discovery layout.

"Clean up YAIML", "compress YAIML", "compact project memory", "prune project memory", or "prune SoT" means remove stale or repetitive memory while preserving current truth, direction, evidence, and uncertainty.

Memory is versioned with this repository and may be public or become public. Never write drive letters, home or profile directories, local workspace paths, personal account URLs, credentials, tokens, private transcripts, raw sensitive logs, local/private URLs, or private personal detail into it. Describe sensitive evidence by location and owner instead of copying it.

See the Maintainer Guide for local YAIML maintenance.
